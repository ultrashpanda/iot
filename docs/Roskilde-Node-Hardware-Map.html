SUMMARY · 5 NOV 2026

Technical decisions

The design choices settled so far, with the technical reasoning behind each. The sections below show them as diagrams.

Hardware and power

DecisionTechnical description
Power tree3×AA Li-ion cells (steady 4.5 V) feed Pro Mini RAW. The Pro Mini's LDO makes 3.3 V for the MCU and the RFM95. The ESP-01 gets switched 4.5 V into its adapter's own LDO, so its 70–300 mA never loads the Pro Mini regulator.
Sensors powered from pinsMAX4466 VCC from D7 and DHT22 VCC from D5 (with its 10 kΩ pull-up to D5). Both draw a few mA at most, well within the 40 mA pin limit, and draw nothing between measurements.
ESP power switchIRF4905 P-FET as high-side switch, gate pulled up to BAT+ by 100 kΩ and pulled low by a 2N2222A driven from A3 through 10 kΩ. A3 HIGH = ESP on. Suggested additions: 100 kΩ from base to GND, so the ESP stays off while A3 floats during reset and flashing, and 220–470 µF at the ESP input against supply dips. The IRF4905 only gets −4.5 V gate drive, so measure its voltage drop during a scan.
No back-poweringBefore cutting power, D3, D4 and D6 are set to plain INPUT with no pull-up. This stops the ESP being fed through its TX/RX pins and the DHT22 through DATA.
Low-power designWatchdog deep sleep in 8 s steps, RFM95 in sleep, Pro Mini power LED removed. Rough budget: ≈ 4.5 mA average, about 90 % of it spent in the Wi-Fi scan, so scan time and interval are the main levers on battery life. To be replaced with measurements.
ESP adapterExposes all pins (GPIO0, GPIO2, EN, RST, TX, RX). EN and RST must sit at 3.3 V when powered. GPIO0 goes to GND only when flashing.

Firmware and data

DecisionTechnical description
Sound measurementA0 sampled continuously for 10 s. The DC offset (≈ ½ VCC) is subtracted, and Leq is computed from the mean of squared samples: dB = 20·log10(Vrms/Vref) + calibration offset, together with the peak. The mic gain is fixed once set, because the calibration depends on it.
Pro Mini ↔ ESP protocolSoftwareSerial at 9600 baud. ESP sends READY after boot. Measurement: SCAN <s> <router hashes> → COUNT n, AP <every router hash heard>, END. Power-up: LOCATE → up to 5 × BSSID + RSSI, END.
Phone privacy (salt)At the start of each scan, the ESP makes its own random salt with its hardware random number generator. Probe-request MACs are hashed with it and kept in RAM only, and only the count leaves the node. Hashes can't be linked between scans, and no salt downlink is needed.
Router filterAny address sending beacon frames is a router and is never counted. The Pro Mini keeps router hashes only (fixed salt, 2 bytes each, no timestamps) in two RAM lists of up to 48: this hour and last hour (192 bytes). Every router heard goes into this hour. Hourly, last hour is dropped and this hour takes its place, so a router is forgotten 1–2 h after it was last heard. Fallback if RAM is short: 2 × 32.
RAM over EEPROMEEPROM wear wasn't the problem (288 writes a day against ~100,000 per cell). Without a clock, though, stored ages are meaningless after a reset, so the list would be wiped anyway. RAM is simpler and costs no write time.
PayloadsPort 1, 8 bytes: avg dB ×2, peak dB ×2, device count (cap 255), temperature ×10 (int16), humidity %, status flags. Port 2, at power-up: flag + up to 5 × (6-byte BSSID + 1-byte RSSI) = 36 bytes max, under the 51-byte limit at SF12.
Downlink (port 1)0x01 interval in minutes, 0x02 scan time in seconds, both range-checked and written to EEPROM only when changed. 0x03 blinks the D13 LED only after LMIC has finished TX/RX, then D13 goes back to SPI.

Geolocation and server

DecisionTechnical description
Geolocation APIGoogle Maps Platform Geolocation API, called from the server so the API key never leaves it. It needs at least 2 access points per request, and the server needs a Google Cloud project with billing enabled.
Position checksFewer than 3 access points sets a flag in the port 2 uplink. The server then keeps the previous position and shows “might have moved”. It shows the same warning when a new fix is more than 100 m from the previous position.
Installation positionRecorded with a phone's GPS at each node at installation, validated on a map straight away, and stored as the first previous position. It stays editable on the server so it can be corrected or updated if a node is moved.
Expected limitationCampsite access points are mostly temporary festival Wi-Fi and phone hotspots that Google hasn't mapped, so the installation position will often be the one used. Test the lookup at the campsite before the festival, and mention this in the report.

SECTION 4

Bench checks before writing code

Points in the circuit worth checking on the breadboard. Orange items may need a small hardware change; green items only need a quick look.

  1. Add a 100 kΩ resistor from the 2N2222A base to GND. During reset, boot and flashing, A3 is a floating input, so the ESP can switch on partly or at random. The pull-down keeps it off until the firmware drives A3.
  2. IRF4905 gate drive is only −4.5 V. Its on-resistance is specified at −10 V, and the threshold can be as high as −4 V. Measure the voltage drop from source to drain while the ESP scans. If it's more than a few hundred mV, or the ESP resets, use a logic-level P-FET instead.
  3. Add 220–470 µF at the ESP adapter input. When Q1 switches on, the adapter's capacitors charge from the battery, and Wi-Fi draws current in bursts. Without a local reservoir, RAW can dip and reset the Pro Mini. Watch for a reboot at the moment A3 goes HIGH.
  4. Back-powering applies to D3 and D6 as well as D4. SoftwareSerial turns on the internal pull-up on its RX pin (D3), which can feed the unpowered ESP through its TX pin. D6 left HIGH would feed the DHT22 through DATA. Set D3, D4 and D6 to plain INPUT before cutting power.
  5. Remove the Pro Mini's power LED. It draws more current than everything else in sleep. Also check which regulator your clone has, because its quiescent current sets the sleep floor.
  6. Allow settling time. The DHT22 needs about 1 s after power-on before its first reading (reading at 2 s, 4 s and so on is fine). Discard the first ~100 ms of mic samples while the amplifier's output settles.
  7. Port 2 payload size is fine. A flag byte plus 5 × 7 bytes is 36 bytes, which is under the 51-byte limit at the slowest EU868 data rate (SF12).
  8. Supply budget is fine. D5 and D7 source only a few mA (40 mA pin limit). The RFM95 at +14 dBm (≈ 40 mA) is within the Pro Mini LDO rating. The ESP has its own regulator, so it never loads the Pro Mini's.

Router list: RAM or EEPROM decided: RAM, hashes only

RAMEEPROM
Survives reset or battery swapNoYes
Uses scarce RAMYes, 192 bytes (2 × 48 hashes)No
WearNoneNot a real problem: 288 writes a day is far below the ~100,000-write life of each cell
Speed and powerInstantAbout 3.3 ms per byte written, so slightly more awake time
Code complexitySimpleMore: write only changed bytes, check validity at boot

EEPROM's only advantage is surviving a reset. Without a clock, though, the stored ages can't be trusted after a reset, so the list would be wiped anyway. Losing the list also costs little, because the ESP already ignores any address it hears beaconing during the same scan. If LMIC leaves less RAM than expected after the first compile, 2 × 32 hashes (128 bytes) is the fallback.
